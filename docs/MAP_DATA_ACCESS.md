# Map data access and flood-event monitoring

Texas is the operational query scope. Kerrville is the bounded test case for historical data, routing and simulated inspections. The raw intake interface is the integration point for a future normalizer. The monitor demonstration runs independently of the application database. The existing dashboard still uses the adapters in `backend/evidence/ingestion.py` and its existing store. Its simplified fields and counts of rejected records cannot substitute for a replayable ingestion history.

## Run and integrate

The statewide implementation passed 399 backend tests with MongoDB enabled, 80 frontend tests and the frontend production build. Browser checks against the local app verified the Texas map, 15-minute selection, desktop and mobile layouts, with no browser errors or horizontal overflow. These checks verify the collector and display behavior. The later normalization, quality assessment and durable event integration remain open.

### Near-live source selection

Open `/texas` for statewide monitoring. `GET /api/feeds/recent?max_age_minutes=30` requests NWS active alerts for `area=TX`, USGS latest gage-height readings for Texas FIPS `48` and NWS Local Storm Reports for the entire state from Iowa Environmental Mesonet. Use `scope=kerrville` for the original point and station test. The statewide map uses the geographic features returned by these providers. The Kerrville road graph supplies the local simulation only.

The inclusive freshness window is 15–30 minutes. Evaluate a gage by its sample time, a road report by its observation time and a bulletin by its issue time and valid interval. Statewide NWS and USGS collectors follow provider cursors. The USGS request uses a rolling one-hour lookback before the stricter read-time filter. Each server process shares a poll across clients of the same scope for up to 60 seconds and reevaluates freshness on each read. Source status `complete` means the requested provider result was read successfully, including a valid empty response. `partial` retains usable results if another page or record failed. `unavailable` means no usable live page or record. All three statuses describe retrieval coverage. Station outages, unreported roads and missing pavement depths remain unknown.

At 10:06 p.m. CST on November 7, 2026 the statewide HTTP endpoint returned 366 recent gage series from 321 distinct stations, two recent flood bulletins and zero qualifying road reports. These are a point-in-time check. The source examples preserve the response formats. `feeds.collect_raw(cache_only=False)` returns statewide raw envelopes for all three providers. For a repeatable offline test, use `collect_raw(scope="kerrville", cache_only=True)`. These local fixtures carry their original geography. A future consumer can implement `feeds.intake.IntakeConsumer`:

```python
from feeds import collect_raw
from feeds.intake import IntakeConsumer

async def deliver(consumer: IntakeConsumer) -> None:
    for envelope in await collect_raw():
        await consumer.receive(envelope)
```

| Envelope fields | Semantics in the implemented collector |
|---|---|
| `source_id`, `source_record_id` | Stable feed ID and optional provider ID. Latest and historical gage products both use `usgs_gage`. |
| `attempt_id`, `record_index` | One ID shared by records from the same request, with a zero-based position. An empty or failed request emits a marker. |
| `retrieved_at`, `payload_retrieved_at` | UTC time of this intake and original fetch time when known. Reading an old cache creates a new attempt. |

| `provider_metadata` | Endpoint and product, allowlisted HTTP metadata and provider collection fields when supplied. `has_next_page` describes an individual page. The Texas alert and gage collectors follow cursors and emit a failure marker if they cannot complete pagination. |
| `raw_payload`, `retrieval_status` | Decoded JSON record or marker. Status is success, empty, malformed or failed. Success only identifies an extracted record. |
| `provenance`, `errors` | Live, cached or unavailable, plus error codes. A usable cached result can carry the failed live attempt's reason. A non-JSON body produces a decoding error and fallback, with no raw body archive. |

The per-product files in `data/feeds_cache/` are replaceable fallback snapshots. Public examples under `docs/examples/map-data/` are fixed. Neither is an append-only source of intake history. ## Handoff and proposed observation contract

Collection owns network access, request scope, fallback and lossless provider field values in decoded JSON records. A later consumer should record each attempt before interpreting its records. One successful empty response records source health. A failed request supplies an error. Neither outcome conveys a change in flood conditions. Track live success, cache use, schema errors and partial coverage separately.

The proposed accepted observation extends the vocabulary of `evidence.models.ObservationIn`. This is a design for a versioned successor. Passing the following fields into today's strict model would require a migration.

| Fields | Meaning and admission rules |
|---|---|
| `schema_version`, `id`, `logical_key`, `revision`, `supersedes_id` | Immutable observation-version ID and the logical record it revises. Give each correction a new ID. Keep expired evidence queryable by ID. |
| `source_id`, `source_record_id?`, `raw_record_ids[]`, `normalizer_version` | Keep each provider ID verbatim, alongside a source-scoped logical key and links to all contributing raw inputs. Require traceability for acceptance. |
| `kind`, `meaning`, `subject_id` | Examples include warning validity at an affected area, gage height at a station, and an impact threshold at a reference point. Reference points belong in a reference layer with an explicit meaning. The road-access default is unknown. |
| `observed_at?`, `issued_at?`, `valid_from?`, `valid_until?`, `provider_modified_at?`, `ingested_at` | Store UTC instants with original strings, offsets, precision and roles. Use BSON dates for time queries and preserve finer precision in originals. Require timestamps according to kind. Receipt of a cached record never renews its validity. A warning's issue time and a sensor's sample time have different meanings. |
| `geometry?`, `location_role`, `area_refs[]`, `geometry_source`, `precision?` | GeoJSON WGS84 longitude/latitude. Validate finite coordinates, range, dimensionality, geometry type and polygon topology. Retain original CRS and any transformation. A zone-only alert can be accepted for nonspatial use with its zone IDs. Admit it to spatial queries only after a versioned zone lookup. |
| `measurement?` | Keep original value, unit and quantity alongside standardized value/unit, conversion version, vertical reference, station datum/epoch and method, as applicable. Preserve an explicit unknown. Validate finite values and compatible units. Converting feet to meters cannot align vertical datums. |
| `method?`, `provider_flags[]`, `source_mode`, `simulated` | Preserve provider vocabulary and unknown codes. Link back to retrieval provenance. Keep synthetic examples distinguishable from operational evidence at every read boundary. |

A normalizer consumes each envelope and returns a tagged outcome. An accepted result carries the above observation candidate and its raw links. A quarantine result carries raw links, field paths, original values or protected references, reason codes and rule version. Reference-only rows can be explicitly routed to a reference dataset. A documented out-of-scope product gets a recorded disposition. Empty and failed attempts stay at the attempt level. Replay must account for every input, including malformed siblings in a successful response.

### Validity, quality, freshness and priority

Record validity is an admission decision. For example, `AMBIGUOUS_UNIT`, `INVALID_COORDINATES` and `OFFSET_MISSING` can quarantine a measurement. A valid provisional gage reading can still be valuable. Store independent assessments with `rule_set_id`, `rule_version`, `assessed_at`, reason codes and related evidence IDs. Candidate dimensions follow.

| Dimension | Example category and reason |
|---|---|
| Authority and provenance | Agency sensor, official bulletin, local report or unknown. Record issuer, product, live/cache origin and lineage. |
| Time and applicability | Current, stale, expired, future or unknown **as of** an evaluation time. Evaluate the validity interval and product-specific age policy from provider time. Record the next reevaluation time where possible. |
| Location precision | Station point, surveyed reference point, warning polygon, zone approximation or unresolved. Record scale, uncertainty and derivation when known. |
| Measurement method and flags | Sensor reading with `USGS_PROVISIONAL`, approved measurement or unknown method. Preserve raw qualifiers for reinterpretation. |
| Completeness | Sufficient for a named use, partial or missing required context. For example, `VERTICAL_DATUM_UNKNOWN` blocks a terrain comparison. |
| Agreement | Corroborated, conflicting, independent evidence unavailable, or incomparable. Store comparison IDs, spatial/temporal window and quantity. The same observation from two USGS products counts once. |
| Verification | Unreviewed, provider-reviewed or independently verified. Record verifier role, time and method. |

Rules return categories with reasons. The downstream map decides operational priority from consequences such as loss of a neighborhood's last exit. A change in that priority does not revise a provider observation. A freshness query reevaluates the clock even when the source sends nothing.

## Proposed MongoDB storage

Build on the current replica-set store in `backend/evidence/mongo_store.py`. It already has sources, ingestion runs, raw records, observation revisions, a geometry index, roads and inspection tasks. Its raw documents currently come from the legacy adapter's observation body and can already have lost provider fields. Keep v1 readable. Introduce a schema version and an explicit cutover/backfill for map readers after replay tests.

| Collection | Proposed key, relationships and indexes |
|---|---|
| `sources` | Stable configured source ID. Store products, provider, attribution/terms, coverage, expected cadence, scope, units, access constraints and metadata version. Version input metadata used by normalization. |
| `ingestion_runs` | One attempt ID per product/request/page. Record timestamps, sanitized scope, result, counts, pagination coverage, cache age and live failure code. Index source/product/scope plus descending attempt time. Derive health and last live success separately. |
| `raw_records` and `intake_receipts` | Immutable raw content or controlled blob URI plus checksum. Deduplicate content on source plus canonical payload hash. A unique receipt on (attempt ID, record ordinal) links each occurrence to content, provider ID and response metadata. Repeated polls preserve history without duplicating bytes. Preserve original bytes separately if byte-for-byte replay is needed. Cap inline payload size. |
| `observations` | Accepted versions only. Unique (source ID, logical key, revision), immutable version ID as primary key, index on supersedes ID. Track the current revision by a head pointer with compare-and-set. Index subject/time, kind/validity and `geometry: 2dsphere`. Maintain separate nonspatial indexes for records without coordinates. |
| `quarantine` | Unique (receipt ID, normalizer version, issue code, field path). Store disposition, reason detail, first/last processing time and resolution link. Reprocessing retains prior failures for audit. |
| `quality_assessments` | Observation-version ID plus rule set/version, evaluation time and evidence-set fingerprint. Index observation ID/time and reevaluation due time. Preserve old assessments when rules or comparison evidence change. |
| `flood_events` and `event_transitions` | Persistent episode ID scoped by monitor, hazard, area/subject and episode anchor. Each transition records previous/new state, effective and decision times, rule version and reason. Unique (event ID, transition sequence) with idempotency key for the triggering input/deadline. Index active state/area, geometry where available, and time. |
| `event_evidence` | Unique (transition ID, observation-version ID, role). Reverse index observation ID to events. Keep evidence supporting, revising or retracting a decision, even after an observation is superseded. |
| `monitor_configs` and `monitor_checkpoints` | Immutable versions of each monitor's scope, thresholds, units/datum, timing and rule version. Unique cursor per monitor version and partition, with accepted-stream watermark, next expiry and concurrency token. |

Use source-specific logical identity. For USGS time series, test (series ID, measurement time) across latest and history. For CAP messages, retain message identity separately from the alert chain. When a reliable key cannot be established, quarantine for identity resolution. A hash of a mutable record alone cannot identify its corrections. Compare normalized semantic content against the current version, excluding receipt metadata. Keep later returns to an earlier value as genuine new revisions if the provider's revision ordering supports them. Route unresolved ordering conflicts to review.

Consume a committed stream of accepted versions in a restart-safe order. Advance the checkpoint in the same transaction as event transitions and support links, using a unique trigger key to make retry safe. Reevaluate temporal deadlines between arrivals. A poll outage or absence from a partial page cannot close an event. Map analysis reads accepted current versions, eligible spatial context and persisted event/support links, with a separate view for as-of replay. Index only validated geometries. MongoDB's spherical index omits missing geometry. [MongoDB geospatial indexes](https://www.mongodb.com/docs/manual/core/indexes/index-types/geospatial/2dsphere/)

### NWS Local Storm Reports via Iowa Environmental Mesonet

- **Access and coverage.** The public IEM GeoJSON collector requests `states=TX` and UTC `sts`/`ets` for the last 30 minutes. This includes reporting locations across Texas regardless of the issuing weather office. One live check on November 7 at 10:05 p.m. Central returned an empty feature collection. Reports arrive when an observer reports an event and NWS issues it. Neither reporting frequency nor delivery delay is guaranteed. Credit the issuing NWS office, reporter role and Iowa Environmental Mesonet. [Provider query documentation](https://github.com/akrherz/iem/blob/main/pylib/iemweb/geojson/lsr.py)
- **Record mapping.** `properties.valid` is the UTC observation time. `product_id` identifies the issued bulletin and may identify multiple reports. The GeoJSON feature ID can change when the request window changes. Preserve it in raw intake and defer durable identity until report-level deduplication and revisions are implemented. `state`, `county`, `city`, `wfo` and the approximate GeoJSON point locate the report. `typetext`, `source`, `qualifier`, `magf`, `unit` and `remark` retain the event type, reporting party, qualification, magnitude and narrative. Missing values can be null or empty. Vertical datum is generally unspecified. [Historical Texas report excerpt](examples/map-data/texas-lsr-road-excerpt.json)
- **Use in the near-live view.** Require a live fetch, an in-window observation time, Texas state, flood event type and a road mention in the narrative. Treat the selected record as a field report requiring interpretation. A road name can be a location reference. A point may be approximate. Preserve any depth range in the narrative without assigning a depth or closure to a mapped road. The historical Polk County example gives a 6–8 inch range over Johnson Branch Road even though the magnitude and unit fields are null. Exclude old observations when a bulletin is reissued.

### NOAA / National Weather Service active alerts

- **Access and coverage.** `api.weather.gov/alerts/active?point=30.0474,-99.1403` is the Kerrville test query. The operational request uses `area=TX`. The query takes latitude first. NWS requires an identifying User-Agent, recommends at least 30 seconds between requests, and applies rate limits. Alerts change as offices issue, update, cancel and expire messages. Attribute to NWS and retain the issuing office (`senderName`). [NWS API access](https://www.weather.gov/documentation/services-web-api) · [NWS CAP and polling guidance](https://www.weather.gov/documentation/services-web-alerts)
- **Examples.** The Kerrville response contained zero features. A separate national query using `event=Flood Warning` returned an actual warning for DeSoto County, Florida. The latter excerpt includes one feature, with provider identifiers, area, geometry, temporal and categorical fields retained. Free text, sender contact, parameters and other unneeded fields were omitted. Use its own geography when replaying. [Kerrville response](examples/map-data/nws-active-point.json) · [National warning excerpt](examples/map-data/nws-flood-warning.json)
- **Mapping.** Model an advisory/warning with its CAP message identifier (`properties.id`), provider feature URI (`feature.id`), issuer, event type and headline. `sent` is the issue time, `effective` and `expires` bound message validity, and `onset` and `ends` describe expected hazard timing when present. Collection `updated` describes the feed. Preserve original offsets and CAP severity, urgency, certainty, status, message type, scope and references. These are provider characterizations, not numeric measurements. Units and vertical datum do not apply.
- **Validation.** GeoJSON polygons use longitude/latitude. Retain `affectedZones`, `geocode` and `areaDesc` when geometry is null. Resolve zones against versioned boundaries before spatial analysis, never substitute the query point for a warning polygon. Check dates, topology, `Actual` vs test status, event classification and update/cancel references. A null `ends` leaves the hazard end unknown. An empty successful response establishes only that this query returned no active messages. Polling active alerts alone can miss intervening transitions.

### USGS Water Data OGC continuous gage height

- **Access and coverage.** GET `https://api.waterdata.usgs.gov/ogcapi/v1/collections/{collection}/items` with `monitoring_location_id=USGS-08166200`, `parameter_code=00065`, `f=json`. Collections are `latest-continuous` and `continuous`, the latter with `time=PT24H&limit=1000`. These test queries cover the Guadalupe River at Kerrville. Statewide monitoring uses `state_code=48`, parameter `00065` and the latest-continuous collection. The probe returned one latest feature and 286 window features at five-minute spacing. Station cadence, telemetry delay and revision timing can vary. Public access succeeded without a key. USGS offers higher limits with an API key. Budget requests, respect throttling and handle pagination before treating a window as complete. Credit USGS Water Data and preserve the station identifier. [USGS OGC API](https://api.waterdata.usgs.gov/docs/ogcapi/) · [USGS API access](https://api.waterdata.usgs.gov/docs/)
- **Examples.** The latest response is complete. The window excerpt preserves the first and last features and response timestamp, omitting collection links and the original feature count. The last window feature and the latest feature have the same provider ID and time in these captures. [Latest response](examples/map-data/usgs-latest-continuous.json) · [24-hour window excerpt](examples/map-data/usgs-continuous-excerpt.json)
- **Mapping.** Map feature `id` to the provider record identifier. Preserve `time_series_id`, station, parameter and `statistic_id` as strings (leading zeros matter). `time` is the measurement time, `last_modified` identifies provider change time and collection `timeStamp` identifies response generation. The point locates the gage. Map original `value` string and `unit_of_measure` to a measured stage. Parameter 00065 is height above the local gage datum. The feature provides no absolute vertical datum or conversion epoch. Gage height cannot be subtracted directly from a road DEM or interpreted as water depth over a road. [USGS gage datum explanation](https://waterdata.usgs.gov/blog/gage_height/)
- **Validation.** Require matching station/series/parameter, usable coordinates, offset-aware time, finite numeric value and compatible units. Common identity across endpoint views is the series plus measurement instant; distinguish revisions using provider modification time, value and quality fields. Keep `approval_status` (e.g. Provisional), `qualifier` (null here) and `method_category` (UNKWN here). Missing or nonnumeric values, unknown methods and missing qualifiers carry different meanings. Never coerce a missing reading to zero. Preserve outliers for later review; zero and negative stages can be meaningful for a local datum. [USGS modernized field mapping](https://api.waterdata.usgs.gov/docs/ogcapi/migration/)

### USGS Real-Time Flood Impacts reference points

- **Access and coverage.** GET `https://api.waterdata.usgs.gov/rtfi-api/referencepoints/nwis/08166200` returned five reference points for a single site. The excerpt retains one bank record. Public read access succeeded without a key; a guaranteed rate limit, refresh interval and timestamp for the displayed stage were unavailable from the sample. Site coverage depends on available reference points. Thresholds may be revised separately from gage telemetry. Credit USGS Real-Time Flood Impacts and preserve attribution in the description where NWS supplied the impact statement. [RTFI API](https://api.waterdata.usgs.gov/rtfi-api/docs) · [USGS product description](https://www.usgs.gov/tools/real-time-flood-impact-map) · [Bank reference point](examples/map-data/usgs-rtfi-excerpt.json)
- **Mapping.** Provider `id` identifies the reference point. `nwis_id`, `nws_id`, `plot_param` and `plot_series_id` identify the associated station and series. `rp_name` and `description` identify the feature and impact. Associate `latitude` and `longitude` with the impact feature. Keep site, state and county identifiers as provider codes; verify lookup tables before geographic joins. The sample has no survey date, measured-at timestamp, datum epoch, horizontal accuracy or independent confirmation that this location flooded.
- **Validation.** Require a matching station/parameter/series, finite threshold, compatible units and a verified stage reference before comparison. Do not use retrieval time to date the underlying gage reading. A reference point can support an impact inference after joining timed stage evidence; it cannot independently corroborate the gage from which its status was calculated. [USGS interpretation guide](https://waterdata.usgs.gov/blog/api-flood-impact/)

## Questions for the normalization milestone

1. Which source-scoped keys and revision clocks survive corrections, simultaneous sensors, CAP updates/cancellations, deletions and late arrivals? Obtain replay pairs for each.
2. Which station metadata identifies the gage datum, offset, epoch, unit and qualifier vocabulary at the sample time? Who approves conversions between station-relative and geodetic heights?
3. Which zone geometry version and precision may represent a polygonless warning? Which uses can accept a spatially unresolved record?
4. What age limits, clock-skew allowances, expiry rules, partial-page handling and recovery/backfill windows are appropriate per product and use?
5. Which reference-point fields can be joined to a timed gage reading? What verification establishes local inundation or road access?
6. Which raw content can be retained or redistributed, for how long, and with what redaction, licensing and blob storage policy? How should existing rows without original payloads be marked during migration?
7. Who owns quarantine resolution, rule versioning and assessment review? How should correlated feeds, revised evidence and conflicting reports affect an existing event?
8. What unit of event identity should persist across neighboring warning areas or related stations? Validate episode merge/split and reopening rules against reviewed historical events before enabling map consumption.

### MRMS rainfall rate and FLASH runoff guidance

The collectors read the official NCEP directory, select an immutable timestamped product, download its compressed GRIB2 payload and decode the Texas portion with Rasterio/GDAL. The mutable latest alias once returned an incomplete gzip during validation, so it is avoided. Both timestamped data products returned HTTP 200 and decoded successfully during the November 7 check. MRMS PrecipRate at 04:32 UTC and FLASH CREST_MAXUNITSTREAMFLOW at 04:30 UTC each produced 266 preview cells with centers inside the saved Census Texas outline. These are coarse previews at 0.5-degree spacing. Each value is the maximum nonnegative pixel within the surrounding 0.5-degree cell. Edge-cell windows can include neighboring states. The original GRIB sphere/CRS is preserved; coordinate placement is approximate and has no road-level precision claim. [MRMS public access](https://www.nssl.noaa.gov/projects/mrms/MRMS_data.php) · [Product definitions](https://www.nssl.noaa.gov/projects/mrms/operational/tables.php)

MRMS values preserve GRIB units [mm/hr]. Radar-derived rainfall rate is an estimate. FLASH values preserve [m^3/s/km^2], the modeled maximum unit streamflow guidance. FLASH's timestamp is the model product valid time. Its maximum includes a temporal forecast window, and historical training documents disagree on the horizon (six versus twelve hours). Preserve that unresolved version-dependent horizon and verify it before operational decisions. The map's spatial maximum is a second aggregation of this temporal maximum. Neither product establishes pavement depth, passability or a closure. [Current WDTD temporal-product description](https://vlab.noaa.gov/web/wdtd/-/maximum-streamflow) · [MRMS excerpt](examples/map-data/noaa_mrms-excerpt.json) · [FLASH excerpt](examples/map-data/noaa_flash-excerpt.json)

Stable product identity is its timestamped filename plus preview cell index. Preview records retain an immutable remote raw storage reference, original CRS, product code, value, unit, valid time, aggregation and cell size. Keep original GRIB_REF_TIME, GRIB_FORECAST_SECONDS and GRIB_VALID_TIME tags. Read GRIB_VALID_TIME independently of the file retrieval time. Exclude negative sentinels (the relevant products use negative missing/no-coverage codes), NaN and infinity before cell aggregation. Quarantine unknown units, unreadable grids, inconsistent timestamps, unsupported CRS or entirely missing windows in the future normalizer. The remote catalogs have rolling retention; durable raw blob retention for long-term replay remains future integration. These runtime downloads are not committed raster archives.
